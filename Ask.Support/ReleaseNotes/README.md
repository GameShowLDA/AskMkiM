# Каталог выпусков

`ReleaseNotesReader.ReadDirectoryAsync` читает верхний уровень заданного каталога.
Один файл `major.minor.patch.json` описывает один выпуск. Поддерживается
`schemaVersion: 1`; даты задаются как `yyyy-MM-dd`. Все обязательные поля
соответствуют `required`-свойствам моделей. Названия полей — camelCase.
Версии сортируются численно по убыванию; порядок изменений внутри выпуска сохраняется.

Категории: `added`, `changed`, `fixed`, `removed`, `important`, `knownIssue`.
`title` и `summary` выпуска, а также `helpKey` изменения необязательны.
Описание — обычный текст. Проверка существования страницы `helpKey` пока не реализована.

Неизвестные поля, некорректные даты/версии, числовые категории, пустые обязательные
строки, пустой список изменений и повторные ID отклоняются. Ошибка формата содержит
путь файла; каталог не возвращается частично. Пустой каталог допустим,
отсутствующий каталог вызывает ошибку I/O. Токен отмены передаётся чтению JSON.

Для отладки из корня репозитория:

```powershell
dotnet run --project TestConsole -- release-notes
dotnet run --project TestConsole -- release-notes "C:\ReleaseNotes"
```

Также доступен пункт меню 23. Без пути используется каталог `AppHelp/releases`
рядом с консольным приложением. Демонстрационный каталог
`TestConsole/ReleaseNotesSamples` можно передать явно; его записи не являются
подтверждённой историей релиза 1.0.0.
При ошибке командный запуск возвращает код 1, при успешном чтении — 0.

Каталог приложения: `Ask.Support/AppHelp/releases/`. Он копируется в output/publish
в `AppHelp/releases/`. Версия 1.1.0 описывает разницу между `origin/main`
(`08149a18f98ff2c05b58a7337a620fd3e54ce8f3`, версия 1.0.0) и текущей
веткой на `a018a771` (версия 1.1.0). Дата 2026-10-21 согласована пользователем.
Источники: diff production-кода поиска, сравнения, выполнения, протоколов,
`PeCommandParser`. Состав публичного описания и формулировки согласованы пользователем;
метрологические погрешности в описании не публикуются. Дополнительно включена реализованная
в текущей рабочей ветке история выпусков в справке; уведомлений об обновлении пока нет.

Проверка фактического каталога из корня репозитория:

```powershell
dotnet run --project TestConsole -- release-notes Ask.Support/AppHelp/releases
```

Чтение JSON не запускает UI, HelpServer или оборудование. `ReleaseNotesHtmlRenderer`
строит HTML с группировкой категорий, экранированием всех текстов и ссылок helpKey.
Локальный `HelpServer` обслуживает `/ru/Content/ReleaseNotes.html` из каталога JSON
на каждый запрос без записи HTML на диск. Раздел `ReleaseNotes` в дереве справки
и меню приложения «Справка → Что нового» открывают эту страницу. Последняя версия
раскрыта, предыдущие свёрнуты; переключение темы наследуется от справки.
При ошибке чтения сервер возвращает 500 с понятным сообщением, причина записывается
в журнал; остальные страницы продолжают работать. Пока содержание только русское,
поэтому этот пункт явно открывает русскую справку и при английском языке приложения.
На главном пустом экране кнопка `ReleaseNotesPrompt` предлагает открыть изменения
установленной версии, пока текущая роль их не посмотрела. После загрузки страницы
`release-notes.js` отправляет POST `/api/release-notes/viewed` с ролью и версией;
сервер сверяет роль с текущей сессией и версию с каталогом. Поэтому меню и дерево
справки тоже засчитывают просмотр, а загрузка HTML индексом поиска — нет.
`ReleaseNotesReadStateStore` сохраняет отметки в
`%LocalAppData%/AskMkiM/ReleaseNotes/state.json` отдельно по ролям и версиям.
Changed скрывает кнопку, новая версия/роль снова её показывает.
Для root в административном меню доступен сброс просмотра текущей версии:
`Admin.ResetReleaseNotesViewCommand` вызывает `ResetViewed` только для root и
установленной версии. Кнопка возвращается через Changed без перезапуска;
история других ролей и версий сохраняется.
Автоматические уведомления при обновлении пока не подключены.

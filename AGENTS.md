# Repository Agent Instructions

## Architecture Map

1. Перед широким исследованием репозитория сначала прочитай
   [`docs/ARCHITECTURE_MAP.md`](docs/ARCHITECTURE_MAP.md).
2. Используй карту, чтобы определить затрагиваемые проекты, типы, точки входа,
   DI-регистрации и runtime call chains.
3. Не сканируй весь репозиторий заново, если карта содержит достаточно сведений
   для навигации по текущей задаче.
4. Для изменяемого участка обязательно проверь актуальный production-код.
5. При конфликте карты и исходного кода доверяй исходному коду и исправь карту.
6. После архитектурно значимого изменения обнови только затронутые разделы карты,
   сохраняя стабильные заголовки, anchors и внутренние ссылки.
7. Обновление карты входит в Definition of Done для изменений проектов,
   зависимостей, DI, интерфейсов, реализаций, adapters, drivers, factories,
   call chains, Real/Idle, error/event flows, background operations, БД,
   конфигурации и основных UI-потоков.

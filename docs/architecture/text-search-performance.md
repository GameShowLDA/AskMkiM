# Проверка производительности поиска

Дата: 2026-10-20. Локальный Release-замер, .NET 8, один процесс; 5 измерений
после прогрева. Это измерение ядра поиска, без времени WPF-отрисовки.

Набор: 8 документов, 13 376 000 символов, 352 000 совпадений; буквальный запрос
«напряжение», без учёта регистра, целое слово. Результаты до/после сравнивались
полностью: порядок, ID документов, смещения, длины, строки и колонки совпали.

| Реализация | Медиана | Средние аллокации за проход |
| --- | ---: | ---: |
| До: Regex.Matches, последовательные документы | 298,44 мс | 99,26 MiB |
| После: EnumerateMatches, ограниченное распараллеливание | 76,55 мс | 57,59 MiB |

На этом наборе ускорение ядра — 3,9 раза, аллокации уменьшились примерно на 42%.
Цифры зависят от CPU, размера файлов и количества совпадений; они не описывают
время полного UI-перехода. Дополнительно устранены повторное сканирование
неизменённых документов, пересоздание всех маркеров при каждом шаге и обработка
невидимых маркеров. Эти свойства проверяются интеграционными тестами, а не
нестабильными временными порогами.

Проверки: Services.TextSearch в Ask.UI.UnitTests — параллельный/последовательный
результат, повторное использование диапазонов, два файла с одинаковым именем,
циклические переходы, пересчёт только изменённого файла, массовая замена и Undo,
инкрементальная подсветка сравнения, пагинация, отмена устаревших результатов.
